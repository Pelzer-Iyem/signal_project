# Data Storage System

This subsystem is responsible for securely storing, retrieving, and managing patient cardiovascular data generated by the CHMS simulator. The design separates storage management, access control, and retrieval responsibilities to improve modularity and maintainability.

The DataStorage class acts as the central storage component responsible for saving patient data, retrieving historical records, and enforcing retention policies through automatic deletion of outdated information. Each PatientData object contains timestamped cardiovascular measurements such as heart rate, blood pressure, and oxygen level readings.

The DataRetriever class handles data queries from authorized medical personnel while delegating permission verification to the AccessController. This separation ensures that security logic remains independent from retrieval logic. The AccessController determines whether a staff member has sufficient privileges to access sensitive patient information.

To support accountability and traceability, the system records all access events in the AuditLog. This improves transparency and helps satisfy privacy and security requirements expected in healthcare systems. The DatabaseRecord class supports versioning and archiving of stored records, enabling future historical analysis and controlled record management.

Composition is used between DataStorage and PatientData because patient measurements are fully managed by the storage subsystem. Aggregation is used for DatabaseRecord objects because records may continue to exist independently during archival processes. Overall, the design prioritizes secure data handling, scalability, and maintainable separation of responsibilities.
